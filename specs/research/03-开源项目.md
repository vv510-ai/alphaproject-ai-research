# 第四课：哪些开源项目可以复用

2026-10-23 补充：结合两版现状重新检查相关 GitHub 项目，当前学习重点与统一建议见 [GitHub 学习与两版统一方案](06-GitHub学习与两版统一.md)。下文保留 10 月 16 日的初筛与当时版本，不把历史统计改成当前数据。

调研日期：2026-10-16。对应课堂笔记“调研主题 3：开源项目”。范围是 `AlphaProject-Lab` 的 A 股行情与 AI 分析助手：自选管理、通知通道、行情看板、AI 解释、异动检测、早盘简报；首页以自选列表为主。

**本课结论：优先使用现成的行情、图表、通知和定时组件；参考相近项目的流程，按明确边界考虑少量模块复用。当前没有选定要整体 fork 的项目。**这是初版复用建议，最终组合还要经过下一课实现方案比较和小实验。

盘中行情验证已按用户要求记为 **DATA-01 待办**，见 [02-数据来源](02-数据来源.md)。本课完成公开资料、许可证、部分核心代码与发布版本核验；没有安装、启动或接入候选应用，没有发送消息。

## 1. 先理解这一步在做什么

可以把系统理解为几块零件：取行情、保存自选、画图、判断异动、生成解释、发通知。开源调研要回答：别人做好了哪一块，接进来还缺什么，我们今后是否维护得动。

本次实际按以下顺序做：

1. **按功能找项目。**同时查完整股票应用、数据工具、图表库和官方通知 SDK，避免只搜“量化交易”得到一堆暂时用不到的交易框架。
2. **看使用条件。**核对仓库里的 LICENSE 和 NOTICE；源码可见不代表每个目录都能按相同条件复制。
3. **顺着代码看依赖和失败路径。**例如通知文件是否还依赖整个项目，行情失败时是明确报错、保留旧数据，还是生成模拟数据。
4. **给出使用方式。**“安装一个发布包”“取一个有边界的模块”“学习设计”“暂不采用”是不同决定；发现候选不等于已经接入。

Star 只记录关注量，最近提交只记录维护活动。它们都不能证明行情准确、AI 分析正确或通知可靠。

## 3. 各项目能帮什么，缺什么

下表的难度是相对当前 Python 取数实验、Web 产品目标作的判断，不是已经测得的开发工时。“高”主要指还需迁移产品结构或承担较多依赖与维护。

| 候选 | 可复用或借鉴的部分 | 对我们的主要缺口 | 本轮建议与接入难度 |
| --- | --- | --- | --- |
| AKShare | 历史行情等数据接口 | 来源时间、单位、失败与备用切换仍需统一；接口库许可不代表数据授权 | 包复用；局部低，稳定数据接入中；已有日线实验 |
| efinance | 股票数据查询、统一表格输出 | 已查的日线仍请求东方财富，与现有东财路径并非独立备用源 | 备用候选；低到中，暂不重复引入 |
| daily_stock_analysis | 多源取数、分析流程、报告、通知结果与去重设计 | 现成模块有项目依赖；部分去重只在进程内生效；需按本产品范围裁剪 | 重点参考；小模块中，整仓高 |
| OpenStock | 自选列表与详情页组织、增删逻辑 | 自选逻辑依赖登录与 MongoDB；文档未确认 A 股报价和提醒支持 | 界面/行为参考；整仓接入高 |
| go-stock | A 股行情、异动提醒、AI 分析的产品组织 | 桌面运行和 Wails 调用需迁移为 Web 服务；当前功能远超六模块 | 产品参考；迁移高 |
| OpenBB | 多提供方的数据模型和插件组织 | 需核验 A 股具体提供方、权限与字段；不是现成自选提醒产品 | 数据架构参考；中到高 |
| FinceptTerminal | 金融信息的分类与展示 | 桌面体系与目标不同；附加许可条款需先厘清 | 公开界面参考；当前不取用代码 |
| TradingAgents | 分析输入、分角色流程、报告与恢复机制 | 多轮模型调用成本和时延未测；不直接提供本产品六模块 | AI 流程参考；完整引入高 |
| TradingAgents-CN | A 股研究产品的交互和功能组织 | 应用前后端等目录许可受限；不是全仓统一开源 | 公开产品参考；受限目录不纳入复用清单 |
| Lightweight Charts | 已取得日线的 K 线与走势展示 | 不提供行情；字段映射、时间、空数据和手机布局由我们处理 | 正式包首选候选；低到中 |
| KLineChart | K 线、技术指标与画线交互 | 仍需接数据；是否需要这些操作由需求阶段决定 | 图表备选；低到中 |
| vn.py | 行情事件、交易网关和策略框架 | 当前不做下单、交易账户或交易终端 | 暂不引入；接入范围大 |
| Qlib | 数据集、特征、训练与研究评估 | 当前不训练预测模型；需要额外数据与实验体系 | 研究扩展候选；当前不引入 |
| Backtrader | 历史策略回测 | 当前六模块没有回测验收目标；不能证明未来收益 | 暂不引入；以后有明确回测需求再核验 |
| 飞书官方 SDK | 创建消息等开放平台 API 调用 | 目标群、应用权限、卡片内容、失败重试与实际送达仍需完成 | 通知候选；中；选定应用机器人方式后用 |
| APScheduler | 按指定时间执行任务 | 不知道 A 股交易日，也不自动解决业务去重和任务失败 | 采用稳定发布包的候选；低到中 |
| StockWatch | 自选提醒、通知卡片、提醒历史和反馈入口 | 已查看的推送代码耦合项目配置；完整产品和策略尚未实测 | 提醒设计与卡片参考；局部中 |
| stock-tracker | 小型 Web 看板、时间/缓存标记的设计 | 部分失败路径生成模拟行情，不符合本工程真实数据要求 | 仅参考界面和状态表达；数据模块不直接采用 |

## 4. 从具体代码得出的五个判断

### 4.1 数据备用要看真正的上游

`efinance/common/getter.py` 的日线函数仍调用 `push2his.eastmoney.com/api/qt/stock/kline/get`。因此，将“AKShare 的东方财富接口”换成 efinance，不能直接算增加了一家独立的数据提供方。它可能有不同的请求实现，但同一上游或访问路径出问题时仍可能一起失败。[已核对源码](https://github.com/Micro-sheep/efinance/blob/c8fd370a3109b2d14a121e3a32a86e9c8354b01b/efinance/common/getter.py#L110)

**对本工程的决定：**保留前两课已实测的东财/腾讯区分，以及真实来源、时间和单位信息；先不为了凑“多个数据源”增加另一个库。AKShare 日线实验通过的范围见 [02-数据来源](02-数据来源.md)，不能由此扩大为所有接口都可用。

### 4.2 daily_stock_analysis 值得学，但需要拆清边界

已检查 `data_provider/base.py`、`src/core/pipeline.py`、`src/notification.py`、`src/notification_noise.py`、依赖清单和 CI 配置：

- 数据管理器按来源尝试、收集失败原因，并在全部失败后抛错；这与我们的来源切换需求接近。
- `notification.py` 依赖配置、报告语言、消息路由、格式化和多个渠道发送器；它不是复制过来就能独立工作的单文件工具。
- `notification_noise.py` 相对独立，提供重复抑制、冷却和免打扰规则，但明确将状态放在进程内。重启后的去重、多个进程的协调不能由它自动保证。

**可考虑局部复用的资产：**通知决策的数据结构与这个去重模块。取用前要保留来源和 MIT 声明，检查所需函数及测试依赖；如果需求包含“重启后仍不重复发”，还需持久化发送记录。当前只是候选，没有把外部实现放进应用代码。[数据管理器](https://github.com/ZhuLinsen/daily_stock_analysis/blob/bba8bf51bdbd3badc75a832c52ede058ef5ab871/data_provider/base.py)、[通知服务](https://github.com/ZhuLinsen/daily_stock_analysis/blob/bba8bf51bdbd3badc75a832c52ede058ef5ab871/src/notification.py)、[去重模块](https://github.com/ZhuLinsen/daily_stock_analysis/blob/bba8bf51bdbd3badc75a832c52ede058ef5ab871/src/notification_noise.py)

上游的 [超时故障讨论](https://github.com/ZhuLinsen/daily_stock_analysis/issues/2340) 也提示我们验证“某个来源卡住后，整个任务能否结束”。这是历史问题提供的测试线索，本课没有在当前版本复现，不能断言当前版本仍存在同一缺陷。看到 CI 文件也不等于我们运行并通过了它的测试。

### 4.3 OpenStock 的页面相近，数据和身份模型还不匹配

其 `MARKET_SUPPORT.md` 将可调用的免费报价/提醒主要列为美国股票与加密资产，没有确认 A 股支持。`watchlist.actions.ts` 的增删读取均调用 `requireUserId()`，并连接 MongoDB。页面上的 TradingView 嵌入组件与可自行提供数据的 Lightweight Charts 也不是同一种接入方式。[市场说明](https://github.com/Open-Dev-Society/OpenStock/blob/b1999adbef0ef07a075a712ab062b0d08ac72fbf/MARKET_SUPPORT.md)、[自选逻辑](https://github.com/Open-Dev-Society/OpenStock/blob/b1999adbef0ef07a075a712ab062b0d08ac72fbf/lib/actions/watchlist.actions.ts)、[图表组件](https://github.com/Open-Dev-Society/OpenStock/blob/b1999adbef0ef07a075a712ab062b0d08ac72fbf/components/TradingViewWidget.tsx)

**对本工程的决定：**学习“自选列表进入个股详情”的信息组织；是否需要账号、怎样保存自选，在本工程需求阶段明确。现有生产网站的免登录约定不因本次调研改变。整仓迁移还涉及数据、身份、数据库和 AGPL 条件，当前收益不足以替代从空工程逐步实践的路线。

### 4.4 图表库可以直接用，但要给它真实数据

本次 npm `latest` 元数据是 Lightweight Charts **5.2.1**、KLineChart **10.1.0**。这是调研日的版本，不是已安装版本。前者有 `setData` 与 `update` 等接口，可将前课的日期、开盘、最高、最低、收盘映射后显示；后者适合进一步比较指标和画线需求。[Lightweight Charts 官方入门](https://tradingview.github.io/lightweight-charts/docs)、[KLineChart 官方说明](https://github.com/klinecharts/KLineChart)

**初步首选 Lightweight Charts：**当前明确需要的是自选股行情与日线展示，先验证基本图表即可。若 PRD 明确需要较多内置指标和画线，再与 KLineChart 做同一数据样本的比较。其 v5 有 API 变化，应按选定版本的文档实现，不能混用旧教程示例。[官方迁移提示](https://github.com/tradingview/lightweight-charts/issues/1791)

两者都已读取 NOTICE；KLineChart 的 NOTICE 也包含 TradingView 的版权信息。Lightweight Charts README 要求提供相关署名和链接，接入时一并落实，不把图表误称为自研。[Lightweight Charts NOTICE](https://github.com/tradingview/lightweight-charts/blob/9db7ce733e95303ae1eeb79e664ee9be4ee5e696/NOTICE)、[KLineChart NOTICE](https://github.com/klinecharts/KLineChart/blob/d5bb26f706a6bd8f67eed4ecbbf22cb67a0725df/NOTICE)

### 4.5 不让“接口失败”变成“画出一条假曲线”

补充搜索发现的 `z8-ui/stock-tracker` 很轻，值得看它如何组织页面。但该快照的 `get_index_history()` 在空数据、数据不足和异常时进入 `_mock_index_history()`；后者用随机数生成价格、成交量并返回与真实 K 线相似的数据结构。这里是直接读取到的代码行为，不是运行测试结果；本课未核验其所有页面如何标注这些数据。[对应代码](https://github.com/z8-ui/stock-tracker/blob/acf531982072d76a6c4326a3bf45be010a243906/data_service.py#L839)

**对本工程的决定：**不直接采用这个行情模块。沿用我们的失败约定：取不到就明确显示失败；如果展示缓存，要保留来源时间和过期状态，不能生成模拟价格冒充真实行情。它被暂缓的原因是这个具体行为，和 Star 少无关。

## 6. 对应课程六个功能的复用矩阵

| 我们要做的功能 | 目前可用的资产或候选 | 我们仍要完成的工作 | 后续怎样证明能用 |
| --- | --- | --- | --- |
| 自选管理 | OpenStock 的列表/详情组织；StockWatch 的提醒入口作参考 | 定义增删、重复代码、保存位置和跨设备行为 | 添加一只股票、刷新后仍在、重复添加不重复、删除后消失 |
| 通知通道 | 飞书官方 Python SDK；DSA 的结构化发送结果和去重模块候选 | 先选通知方式，再确认目标、权限、失败状态与发送记录；若只选群 Webhook，未必需要整套 SDK | 经用户授权向明确目标发一条，检查实际收到和消息记录；重复触发不刷屏，失败可见 |
| 行情看板 | 已完成的日线/报价实验；Lightweight Charts 首选候选，KLineChart 备选 | 统一数据、单位和来源时间，处理空数据、旧数据和错误，制作自选首页 | 用保存的真实 6 条日线核对 K 线位置与数值；盘中时效另由 DATA-01 验证 |
| AI 解释 | DSA 的取数—分析—报告流程；TradingAgents 的输入与报告组织作参考 | 设计输入事实、输出结构、缺失提示、证据链接与调用预算 | 给定同一份行情与资料，检查数字能回溯；缺资料时明确不足；模型失败不伪装分析完成 |
| 异动检测 | StockWatch 的提醒设计；DSA 的冷却/去重逻辑候选 | 明确触发阈值、证券交易状态、比较基准、持久化及重新触发规则 | 用正常、触发、重复、过期数据、重启几组场景检查；不把合成测试数据当真实行情 |
| 早盘简报 | APScheduler 稳定版候选；DSA 的报告组织与通知流程 | 交易日判断、资料截止时间、缺数说明、重复运行和失败补偿 | 在指定测试时间只生成一次；检查内容来源与收件结果；实际交易日任务需后续实测 |

这也构成课程要求的生态拼图：**数据接入看 AKShare/efinance/OpenBB，前端看图表库和 OpenStock，回测保留 Backtrader/Qlib/vn.py 作后续候选，推送看官方 SDK 与 DSA，部署方式参考 DSA 的本地/Docker/Actions 组织。**新工程的部署环境和费用在实现方案、部署课程中另行确定，不能直接套用现有生产环境配置。
