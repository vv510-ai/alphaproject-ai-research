# 第十二课：异动检测，把提醒条件变成可追查的结果

日期：2026-10-18。运行版本：0.5.0。范围：本机/局域网学习工程；没有发布到现有生产网站。

**已实现：逐股票规则、后台演练、固定事件依据、同日去重、事件关联的飞书提醒和页面状态。真实盘中监测仍暂停，DATA-01 未通过。**本课有一条合成事件取得真实飞书接收回执；网页收件确认以数据库中的 `confirmed_at` 为准，最新结果见[核验报告](../../evidence/anomaly-20261018/verification.json)。

## 什么是异动检测，为什么做

这里的“异动”是**价格变化达到了你事先设置的提醒条件**。检测程序反复检查这些条件，满足时记录下来并提醒，让你不用一直盯着网页，也能回头查清“为什么提醒我”。

本课先做一条能复算的价格规则。它回答“发生了多大的变化”，不能仅凭这条结果回答“为什么涨跌”或“应该怎样交易”。后续 AI 解释会读取这次事件保存的依据。

## 我们怎样判断

你已经选择：**教学演练上涨 3%、下跌 3%，同一股票同一方向每天最多一次**。两个阈值都填写正数；下跌填 3 表示涨跌幅达到 −3%。真实规则初次关闭，演练不会替你打开它。

计算方法：`涨跌幅 =（当前价格 − 昨日收盘价）÷ 昨日收盘价 × 100%`。

| 合成输入：昨收均为 100 元 | 计算结果 | 系统怎样处理 | 这个例子验证什么 |
| --- | --- | --- | --- |
| 现价 102.99 元 | 上涨 2.99% | 不产生事件 | 差一点达到也不能算达到 |
| 现价 103 元 | 上涨 3% | 保存一条上涨事件，再准备通知 | 正好等于阈值也触发 |
| 现价 103.20 元 | 上涨 3.20% | 不再产生同日同方向事件 | 持续满足不重复打扰 |
| 现价 97.01 → 97 → 96.80 元 | −2.99% → −3% → −3.20% | 不触发 → 触发 → 不重复 | 下跌与上涨使用对称规则 |

计算使用 Decimal，并用未舍入的结果比较；例如 2.99999999% 不会因为页面显示成 3.00% 就触发。若当天第一份有效采样已经超过阈值，标为“首次观察已满足”，不会假装知道价格准确越线的那一瞬间。

检查顺序是：**股票身份正确 → 现价与昨收可用 → 来源时间合格 → 交易状态与盘中时效已核验 → 比较阈值 → 查当天是否已有事件 → 保存证据与待发状态 → 发飞书**。

旧数据、缺昨收、零昨收、未来时间、倒退时间、停牌、休市或状态未知，都不能触发真实事件。演练输入在页面、事件和消息里都标“合成演练 · 非真实行情”，不会写进首页真实报价缓存。

## 体现了哪些产品判断

| 判断 | 本次选择 | 代价或边界 |
| --- | --- | --- |
| 和什么比较 | 用同来源的昨日收盘价，比较百分比 | 只描述相对昨收的变化，不是几分钟内的加速或成交量异常 |
| 多大变化值得提醒 | 由你设置提醒线；本次练习选 3% | 3% 是你的教学选择，不是已验证的最佳交易参数 |
| 怎样减少打扰 | 同股票、同方向、同日只记录一次 | 当天从 3% 继续涨到 10% 也不会再推第二条；以后若需要多级提醒再另定规则 |
| 数据不确定怎么办 | 暂停并说明原因 | 宁可显示暂停，也不把周末旧值当盘中新变化 |
| 怎样让结果可解释 | 先保存触发时的价格、基准、来源时间、规则版本和事件编号 | 后来的行情、改规则或移出自选，都不能改写过去的事件 |
| 通知故障怎样处理 | 事件与发送状态分开保存；未知不自动重发 | 平台接收与本人确认分开；不确定时需要核对群内那条消息 |

## 你现在怎样操作

1. 打开[电脑入口](http://127.0.0.1:18765/)，点“异动检测”。同一 Wi-Fi 的手机可用[局域网入口](http://10.45.146.38:18765/)。
2. 在自选股票下填写上涨/下跌百分比，点“保存规则”。“启用真实行情规则”先保持关闭；页面顶部会说明真实检测为什么暂停。
3. 保留“触发后向已配置的飞书群发送演练提醒”，点“开始上涨演练”；取消该勾选则仅在网页演练。后台会依次检查三个合成价格。
4. 看三步结果，在事件下展开“查看当时依据与事件标识”。演练日期按北京时间记日，不表示当天真实开市。
5. 收到飞书提醒后，核对相同事件编号、价格和来源时间。点击“去核对飞书收件”，把**这条新消息**里的 6 位核验码填到对应发送记录下。核验码仅用于本条学习测试，不是账户登录码。
6. 同一天重复运行上涨演练仍能看到判断步骤，但不会再创建或推送同一方向的事件。下跌是另一方向，首次触发会有独立事件。

本课已经发生的一条消息可直接用于第 5 步，不需要为核对再次发送。

## 工具分别做什么

- **Python / Decimal**：逐项检查证据并计算阈值；这一步没有调用 AI。
- **FastAPI**：网页保存规则、启动演练和读取结果的接口。
- **SQLite**：保存规则、步骤、固定事件和发送状态；唯一键确保同日同方向不重复。
- **Python 后台线程 + 系统文件锁**：独立于网页运行有限任务，阻止两份服务同时执行。当前任务简单，未新增调度库；简报课再评估是否需要独立任务进程。
- **React / TypeScript / Vite**：制作表单、三步结果和事件依据页面，并检查类型、构建静态页面。
- **HTTPX + 飞书应用机器人**：复用上一课固定群通道；没有新增接收者或新收费资源。
- **pytest、浏览器工具与独立复核**：分别验证算法/竞态、真实交互与模块交接，不能互相替代。

所用机制参考：[Python 线程与 Event](https://docs.python.org/3/library/threading.html#event-objects)、[FastAPI 生命周期](https://fastapi.tiangolo.com/advanced/events/)、[SQLite 事务](https://www.sqlite.org/lang_transaction.html)。完整取舍见[本课方案](plan.md)。
