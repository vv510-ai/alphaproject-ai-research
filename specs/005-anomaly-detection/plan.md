# 第十二课：先把一条异动规则做清楚

2026-10-18。用户要求继续实践开发，并解释异动是什么、为什么做、如何判断，让本人参与操作。已选择教学演练：相对昨收上涨 3% / 下跌 3%，同一股票同一方向每天最多一次。该选择不等于已经启用真实行情监测。

## 本课闭环

自选股票 → 保存规则 → 后台检查 → 保存固定事件依据 → 复用单人飞书通道 → 页面核对同一事件。演练使用明确标记的合成价格，不改真实报价缓存；与真实事件分开去重。AI 与早盘简报留到后续课程。

1. 规则按股票保存，初次关闭；涨跌阈值均为正百分比。保存时检查自选身份及规则版本，过期页面不能覆盖新设置。
2. 用 Decimal 计算 `(现价 - 昨收) / 昨收 × 100%`，不先四舍五入再比较。等于阈值也触发。无效、过期、未来、倒退、身份不符或交易状态未知的输入不产生真实事件。
3. 同一股票、方向、日期、真实/演练类别唯一；删自选、重启、回落再越线及改阈值均不清空已发生事件。保存事件时再次检查规则和自选，网络请求不占数据库事务。
4. 后端负责定时工作，网页只读取进度。演练分三步运行，关掉网页仍继续。第二份服务不能同时占用同一数据库执行任务。
5. 事件及待发记录在一次数据库事务内保存；通知关闭仍保存事件。待发消息保留五分钟的教学有效期，重启取消未发演练，发送结果未知不自动重发。真实提醒的 M 仍需盘中验收后确定。
6. 演练可选择实际通知原来的单人群；记录与消息均标“合成演练”，用事件标识和核验码核对。重复演练不重新创建或发送同日同方向事件。

## 已知边界与选择

- DATA-01 仍未通过：目前报价服务明确返回 `market_state=unknown`、`realtime_verified=false`。因此真实检测显示暂停，不把周末旧报价当盘中异动，也不通过模拟结果关闭 DATA-01。当前后台每 60 秒复查已保存数据和资格，尚不开放持续外部行情采集；真实 P/F/Δ、交易日历及停牌状态另验。演练 F=120 秒、Δ=0，是合成测试条件。
- 继续使用现有 FastAPI、SQLite、HTTPX、React，不增加第三方依赖。单一短循环用 Python `threading.Event`/`Thread` 配合 FastAPI lifespan 管理；本机文件锁限定一个执行实例。先前调研的独立 APScheduler 进程是候选，本课尚无多种日程/持久任务需求，因此暂不增加独立部署组件；简报课重新评估。
- 通知沿用已核验的私有群及加密配置，不读取或复制新的生产秘密。保留原有手动测试与核验记录。收到平台回执与本人核验仍分开记录。

## 验证与参与

- 算法：100→102.99→103→103.20；100→97.01→97→96.80；回落/次日/重启/无效值/时效/身份/交易状态/保存竞争。
- 后台与数据：数据库副本、旧版本兼容、单实例、关闭网页后的真实后台演练、服务重启后记录保留、旧事件不可被行情与规则更新替换。
- 通道：事件先保存再发；关闭、过期、未知、重复及成员变化用隔离夹具；经用户界面实际走一次标记明确的演练提醒。
- 页面：桌面及窄屏实际操作，核对触发/未触发/重复结果、错误与焦点；修改不以 HTTP 200 或测试数量替代流程证据。
- 用户亲自操作：保存规则，启动演练，查看三个步骤，核对飞书同一事件。完成后用自己的话说出“比较基准、触发线、重复策略”即可，不设术语考试。
