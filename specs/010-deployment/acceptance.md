# 第十七课：让学习版离开本机，再复盘

2026-10-20，北京时间。用户选择“现有阿里云，给学习版单独开入口”。已发布 [云端学习版](https://8.155.130.86/lab/)，免账号密码，无需本机开机。最终版本 **v0.9.3**，发布标识 `lab-20261019T182526345697Z`。本机已停止，原站保持正常。

## 这一课实际在解决什么

之前网页只是本机程序的入口；电脑停了，页面和定时任务就无法继续运行。部署要把**运行程序、保存数据、访问地址、私有配置、出错恢复**一起安排好。把网页文件上传成功，只解决了其中一部分。

你作出的关键选择是复用现有阿里云。这决定了本课不新购主机，在已有 HTTPS 地址增加 `/lab/`。学习版用独立服务、目录、数据和凭据；原站继续使用根地址。代价是两套应用共享一台主机的资源和故障范围，所以学习版限制了内存、CPU 和并发，仍没有 7×24 可用性承诺。

## 怎么做，以及为什么

| 问题 | 本课做法 | 理由和边界 |
| --- | --- | --- |
| `/lab/` 页面加载了，按钮却请求原站接口 | 网页资源、API、详情链接使用同一前缀；服务以明确配置产生公网地址 | 页面和接口必须指向同一应用。不能从任意请求头猜消息地址 |
| 本机配置到 Linux 无法解密 | 本机仅在内存读取学习版已授权配置，经固定指纹 SSH 传入独立受保护文件，由 systemd 提供给进程 | Windows 用户加密文件不能直接搬到 Linux 使用。凭据不进代码包、命令参数或页面 |
| 电脑和云端同时执行 08:45 任务 | 先确认本机空闲、停止服务并取得数据库独占锁，再迁移；本机启动入口保留云端保护标记 | 这是一次迁移，不是两套数据自动同步；避免重复通知与两边分别计费 |
| 本机测试通过，服务器仍失败 | 在服务器独立测试库运行同一套检查，再用真实学习数据库副本启动候选代码 | 本课实际发现缺少测试目录和四份公开行情样本，均在切换前修正；没有通过删掉测试来发布 |
| 更新覆盖旧结果，或回退丢失新数据 | 代码按版本保存，数据库在版本目录之外；切换前备份，旧代码先检查当前数据副本 | 回退切代码，不回灌旧数据库。数据库结构改变仍需独立兼容验证 |
| 上传、备份、解包中途失败 | 先写独占临时文件/目录，完整校验后发布；迁移重试核对同一备份和回执 | “重试”不能变成覆盖未知数据。无法证明状态一致时停止并查记录 |

以上实现由助手完成。你的部署位置、模型预算、简报时间和内容选择分别保留；不把助手操作和测试写成你已独立实现。

## 如何亲自检查

1. 在电脑或手机打开 [公网入口](https://8.155.130.86/lab/)，点“手机访问”。云端提示应说明无需同一 Wi-Fi、本机关闭后仍可访问。
2. 打开旧的[固定报价解释](https://8.155.130.86/lab/#quote=aada8d51-4138-4df8-b61a-2902f8966ee7)。应仍是 `000001` 的 11.65 / 11.50 元依据，来源时间为 10 月 19 日；打开旧记录不会重新调用模型。
3. 打开旧的[演练事件](https://8.155.130.86/lab/#event=08c72a10-a825-4241-8df0-382d2b9a15e4)。应仍能核对 `103 / 100 / 3%`，并明确这是合成演练。
4. 页脚“查看部署版本”可核对当前运行标识。若页面报错，先记下网址、操作、时间和版本，再判断页面、接口还是数据环节出了问题。

这几步是可继续参与的验收，不要求重复回答术语题，也不把尚未收到的手机反馈标成通过。本人收件确认和 AI 核对仍由本人操作。

## 这次复盘可以怎样讲

“我先确认部署到已有服务器，再把学习版与原站分开。为了让两边只运行一份任务，我要求停掉本机再迁移；为了回退不丢结果，把程序版本和数据分开。服务器检查发现本机环境没有暴露的缺失项，修正后再发布。验收看的是实际读写、旧记录和重启恢复，最后才核对版本号。”

这段可作为你理解思路后的表达练习，不能直接当作个人独立编码经历。进一步复盘时，可以自己指出：哪个选择是你做的、哪个问题由测试发现、哪项结果仍缺证据。
