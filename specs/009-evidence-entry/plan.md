2026-10-19。用户说“我先不发 继续开发”，暂缓上一课手机地址与事件标识核对。本课只补 PRD 已有的 ENTRY-01 与 AIDETAIL-01；不替用户确认收件，不发布生产网站。

## 行为与取舍

- 新异动消息包含“查看这次事件”链接；网页事件和通知记录也有同一入口。按 ID 单独读取，刷新、列表翻页边界和移出自选后仍可查历史。打开只读取，模型生成与收件确认仍要明确操作。
- 股票未触发异动也能解释。先预览已取得的报价，再固定报价；后续解释只用这个快照。缺报价先按原入口获取，身份、单位、未来时间或数值矛盾拦截。旧报价允许作为历史依据，明确来源时间和实时性未验证。
- 沿用既有模型、预算、单次请求去重、失败手动重试和人工核对。普通报价不伪造异动事件。历史快照不随自选删除。
- 数据结构增加独立报价快照，AI 记录允许事件或快照二选一；旧字段值保留，共用用量账本。迁移先在实际数据库副本验证，再启动学习版。旧代码可读旧事件并将新用量计入预算。
- 消息地址来自服务启动时的局域网地址，不采信请求 Host。当前仍要求手机能访问该局域网地址；实际飞书客户端点击留待用户继续验收。

## 检查怎样对应结果

1. 隔离 API 全流程：读报价、固定、生成、缓存、刷新报价、删除、读旧快照、重启；检查没有伪异动及重复费用。
2. 失败：非法价格/时间/身份、页面旧版本、请求号串用、预算和并发；事件原有路径回归。
3. 消息构造：实际 FeishuClient 配合受控 HTTP 返回，校验富文本链接与原核验码正文；不实际发送。
4. 实际数据副本迁移与旧代码兼容、现有数据保留。
5. 构建、实际学习版重启、浏览器桌面/窄屏、直接 URL 与历史前进后退；真实报价固定和至多一次预算内模型调用。助手核对与本人核对分别记录。
